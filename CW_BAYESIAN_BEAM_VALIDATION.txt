Date: 2026-08-05
Base: MadModem_0_5_78_CW_ADAPTIVE_BEAM_FULL_SOURCE

PURPOSE
-------
Separate on-air comparison branch. It keeps the same two user receivers RX A/RX B,
exact-tone DSP, AFC, carrier-session probability, AudioEngine and waterfall.
Only the interpretation of completed CW MARK/SPACE runs is changed.

IMPLEMENTED
-----------
- Per-hypothesis Normal-Inverse-Gamma duration posteriors in log-duration space:
  dit, dah, element SPACE, character SPACE and word SPACE.
- Robust predictive Student-t log-likelihood kernel.
- Fractional posterior updates driven by SNR, coherence, carrier centering,
  mean discriminator MARK probability, QSB probability and estimated noise.
- Broad outlier mixture and probability-controlled noisy-MARK skip path.
- Posterior-mass commit: 98.5% credible-prefix consensus or 99.2% decisive path
  with absolute RF-evidence guard.
- Runtime diagnostics: bayes=<count>/<confidence>, post=<best posterior>,
  odds=<best/second posterior dB>.
- No dictionary, language model, neural model, additional RX lane or extra thread.

SOURCE SCOPE
------------
Production changes are confined to:
- modems/cw/skimmer/CwCarrierDiscriminator.{h,cpp}
- modems/cw/skimmer/CwMorseBeamDecoder.{h,cpp}

No AudioEngine, waterfall, FT8/FT4, CW TX, CAT/PTT or sequencer source was changed.

OPTIMIZED EXECUTABLE-ONLY TIMING IN PREPARATION CONTAINER
---------------------------------------------------------
Bayesian branch (three runs): 1.22 s, 1.29 s, 1.25 s; peak RSS about 8 MB.
Adaptive base   (three runs): 1.30 s, 1.33 s, 1.40 s; peak RSS about 8 MB.

These figures are not a decoder-quality result and the suites are not perfectly
identical because the Bayesian branch adds posterior-specific checks. They show
no measurable live-path CPU or memory regression. Most elapsed time is the
48 kHz synthesized RF pipeline, not the run-rate Bayesian beam.
