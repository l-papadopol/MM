MadModem 0.5.79 — RTTY Contest Rule Engine
Validation report — 2026-08-15

SCOPE
-----
Implemented an RTTY Contest Engine whose contest-specific behaviour is loaded from the external file named exactly "rtty_rules" placed next to the MadModem executable. Contest names, exchanges, macros, serial policy, conditional fields, dupe scope, contest periods, QSO-point rules, multiplier definitions and score formula are data-driven. No contest-name branch was added to the runtime C++ path.

ARCHITECTURE
------------
Normal RTTY remains the default. Contest Mode is explicitly enabled by the operator.

Runtime path:
  RTTY decoder -> semantic RX parser -> one Contest Session -> macro/exchange formatter -> normal RTTY TX

The rule engine does not own a second TX sequencer and does not create autonomous QSOs.

rtty_rules handling:
- schema version: 1
- application-directory file only; there is no embedded rules fallback
- missing/invalid rules disable Contest Mode while normal RTTY remains usable
- Reload rules button reloads the external file without rebuilding MadModem
- CMake/install/package scripts copy rtty_rules beside the executable on Linux/Windows and inside MadModem.app/Contents/MacOS on macOS

CONTEST UI / QSO STATE
----------------------
Implemented:
- Contest Mode checkbox
- contest profile selector
- Reload rules
- explicit New Contest Session control
- next TX serial control
- session/QSO status
- dynamic exchange fields
- CAT/manual band-source indication
- live scoring: session QSOs, valid QSOs, multipliers, QSO points, total score
- profile-driven macro buttons

Serial transaction rules:
- the serial is frozen for the current QSO
- retries/repeats reuse the same serial
- serial increments only after the QSO is successfully appended to the log
- a conditional SERIAL field only consumes a serial when that field is active for that QSO
- a new serial sequence is started only by an explicit New Contest Session action

RX PARSING / CLICK-TO-FILL
--------------------------
Contest profiles declare the fields expected in RX and TX exchanges. During Contest Mode, received callsigns retain the existing highlighting, Maidenhead locators are highlighted/clickable, and profile-specific received values such as SERIAL / zone / province / year / area are highlighted and can fill the corresponding structured QSO field. Conservative auto-fill is used only when the interpretation is unambiguous.

CAT BAND
--------
When CAT is connected and a valid rig frequency is available, the contest band is derived from CAT and is authoritative/read-only in the Contest UI. Without CAT, the band remains manually selectable. No hidden fallback chain exists.

LOG / SESSION / SCORE
---------------------
The log stores contest profile ID, rules/session identity, sent and received exchanges, STX/SRX and structured contest fields. Score is rebuilt from the current contest session in the log rather than living only in volatile RAM.

Generic score engine supports:
- dupe scopes: overall, band, period, band_period
- QSO points: first matching conditional rule; distance_km method where explicitly requested
- multiplier sources: dxcc, continent, cq_zone, call, call_area, wpx_prefix, regex-captured callsign component, profile field, and legacy generic dxcc_or_call_area
- multiplier scopes: overall, band, period, band_period
- score variables: QSO, POINTS, MULTS, CONTINENTS
- generic boolean/profile conditions; unknown condition keys fail safe

RULE COVERAGE
-------------
rtty_rules contains 30 profiles: 29 active profiles plus Open Ukraine RTTY marked cancelled for 2026. The profile set was built by cross-checking a broad RTTY contest catalog/calendar and organizer/current rule pages. It is intentionally an external data set so rule corrections can be shipped by replacing rtty_rules rather than rebuilding the application.

Live scoring is intentionally marked unsupported rather than approximated for:
- Alessandro Volta RTTY DX: exchange-point table is too contest-specific for the current generic score primitives
- WAEDC RTTY: QTC accounting is not represented yet
- ARRL Rookie Roundup RTTY: exact scoring depends on Rookie/non-Rookie status not currently represented as a structured station attribute
- Open Ukraine RTTY: cancelled/inactive profile

The rule catalog in RTTY_RULES_CATALOG_2026.txt records the source URL and notes for every profile.

NOTABLE RULE SAFETY
-------------------
- IG-RY WW RTTY current rules prohibit autonomous/robot operation. MadModem Contest Mode remains operator-guided: it parses/fills exchanges and supplies macros but does not autonomously initiate QSOs or log contacts.
- Cancelled profiles are not offered as active contests.
- Unknown rule conditions do not broaden a rule; they fail safe.
