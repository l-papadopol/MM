Troubleshooting

No receive decodes

Confirm that RX is running, the correct audio input is selected and the level is above the noise floor without clipping. Place the mode marker on the signal. FT4/FT8 also require an accurate UTC clock.

CAT or band change does not work

Check the Hamlib model, port or network address and use the CAT read test. Selecting an FT band tunes the standard dial frequency only while CAT is connected.

TX does not start

Configure a valid callsign and locator under Settings → User/QTH. Then verify the TX audio device, PTT method and radio data-mode routing. The Runtime log records the reason for a blocked FT transmission.

Rotator does not move

Use a rotator connection separate from radio CAT, confirm its mechanical limits and check the MOV/RDY indicators. Never bypass a reported limit or emergency stop.

Session diagnostics

In Settings → Diagnostics, enable complete session diagnostics, choose a folder and press OK. Logging starts immediately and the preference is remembered. Restart with the option enabled to capture startup. Open log folder locates the UTF-8 JSONL file. Normal exit drains accepted events. Audio timing, attempts/rejections, runtime/Qt/Hamlib, UI and TX events are captured; audio samples require the separate WAV recorder. Detailed logging uses CPU/disk and files can grow large. Errors or lost events are explicitly reported; an incomplete file must not be treated as a complete session. Logs are written directly as gzip-compressed .jsonl.gz; decompress with an archive tool or tools/read_session_log.py. All events are retained. Compression runs on the writer thread and disk flushes are batched every 250 ms. An explicit flush still exposes all preceding records. After a crash, --recover extracts the readable prefix and marks it incomplete.
