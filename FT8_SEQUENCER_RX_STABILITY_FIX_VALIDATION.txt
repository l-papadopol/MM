LIVE LOG DIAGNOSIS
==================
1. False adaptive-resource collapse
   - Audio capture remained active with continuous callbacks, low CPU, GPU waterfall,
     and later zero sample gaps/overlaps.
   - The controller nevertheless interpreted currentCaptureQueueLatencyMs as live
     queue pressure and reduced the boundary budget repeatedly down to one worker.
   - currentCaptureQueueLatencyMs is computed from wall-clock age of a sample
     timeline anchored once at capture start. It includes USB/audio-clock drift and
     backend buffering and is not a valid measure of decoder-induced queue backlog.
   - Restarting RX reset the worker budget, matching the observed temporary recovery.

2. Non-idempotent sequencer arms
   - The same message/tag/boundary was armed multiple times within tens of
     milliseconds, creating replacement tokens and watchdogs without changing the
     intended transmission.
   - Anonymous rotator-defer singleShot callbacks survived newer plans.

3. AutoQSO orchestration races
   - AutoQSO ranking did select and complete QSOs in the supplied log.
   - Its apparent failure was caused by rotator guard deferrals, duplicate arms and
     a per-slot RX watchdog racing the normal post-TX RX restart.

4. STOP was not authoritative over queued atomic results
   - A decode already queued in an atomic batch could recreate a QSO and arm a new
     reply after the operator pressed STOP.

SOURCE CHANGES
==============
- utils/SystemResourceManager.cpp
  * sample-timestamp age remains telemetry but no longer drives worker downscaling.
  * live worker targets can still react to actual GUI/waterfall/CPU pressure.

- mainwindow.cpp / mainwindow.h
  * explicit STOP latch blocks late queued decodes until a new manual TX/CQ,
    manual decode/history selection or AutoQSO enable action.
  * identical future TX arms are idempotent.
  * one monotonic rotator-defer generation invalidates stale callbacks.
  * rotator readiness is checked before creating the UTC scheduler token.
  * the per-slot AutoQSO RX restart watchdog is removed; TX completion owns RX restart.

UNCHANGED

- FT TX waveform generation and anti-truncation lifecycle correction.
- CAT/PTT implementation, AudioEngine PCM path, waterfall, CW and other modes.

ENVIRONMENT LIMITATION
======================
The container has no Qt5/Qt6 development packages, so the full GUI application
could not be linked or run here. The first Windows/macOS/Linux CI build and the
live radio test remain mandatory.

FIRST LIVE CHECK
================
1. Keep the rotator guard disabled or rotator disconnected for the first test.
2. Start FT8 RX and leave it running for at least 10 minutes.
3. The resource log must stay at the topology budget; it must never ratchet
   10->8->6->4->2->1 from "audio pressure".
4. Press STOP during an active/pending QSO. A late addressed decode must remain
   visible but must not arm a new SEQ/RETRY transmission.
5. Enable AutoQSO and verify one CQ selection creates one arm line only.
6. Re-enable the rotator guard and verify the UI waits in RX while pointing,
   then creates one scheduler arm after readiness.
