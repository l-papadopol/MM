MadModem 0.5.78 — macOS Homebrew CI fix

Scope
-----
Only the two GitHub Actions workflow files for macOS dependency installation were changed:
- .github/workflows/build-macos.yml
- .github/workflows/build-distribution.yml

Change
------
Removed the explicit `brew update` step and set:
  HOMEBREW_NO_AUTO_UPDATE: "1"
on the Homebrew dependency-install step.

Reason
------
The macOS arm64 runner failed while `brew update` tried to download Homebrew API metadata
(`internal/packages.arm64_sequoia.jws.json`). This is an external Homebrew/API/network failure,
not a MadModem source or AppleClang build failure. The CI only needs the required build formulae;
an explicit metadata refresh is not required on every run.

Audit performed
---------------
- No `brew update` remains in either macOS workflow.
- Both macOS dependency installation steps set HOMEBREW_NO_AUTO_UPDATE=1.
- No MadModem C/C++ source file was changed.
- No build/package script was changed.

Not performed
-------------
No macOS GitHub-hosted runner is available in this container, so the real arm64/x86_64 CI jobs
were not executed here.
